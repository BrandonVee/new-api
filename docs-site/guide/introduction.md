# Ai-gateway 是什么

Ai-gateway 是可以自行部署的 AI API 网关。应用把请求发给网关，网关根据模型、分组和可用渠道选择上游服务，再记录请求用量和费用。你可以在控制台集中维护服务商凭据，应用只持有网关发放的 API 令牌。

## 适合解决哪些问题

- 多个应用连接不同服务商，希望统一访问入口。
- 团队成员需要不同的模型权限和额度。
- 需要查看请求错误、响应时间、用量和结算记录。
- 希望在同一模型名称后维护多个上游，配置优先级与权重。
- 需要通过任务插件接入图像、视频等异步生成能力。

网关本身不提供模型算力，也不会自动获得上游访问权限。调用的可用性取决于上游账号、模型权限、网络、渠道和管理员配置。

## 当前项目的组成

| 目录 | 作用 |
| --- | --- |
| `router/`、`middleware/`、`controller/` | 路由、鉴权、限流与请求处理 |
| `relay/` | 上游渠道适配与转发 |
| `service/`、`model/` | 业务规则、结算与数据存储 |
| `relaykit/` | 独立的协议 DTO 与转换模块 |
| `tokenkit/` | 独立的文本、图像 token 统计模块 |
| `plugins/tasks/` | 图像、视频等 JavaScript 任务插件 |
| `web/` | React 19 控制台 |
| `electron/` | 桌面包装与打包 |
| `docs-site/` | 本使用手册的独立静态站点 |

## 可以使用的接口形式

常见文本接口包括 OpenAI Chat Completions、Responses、Anthropic Messages 和 Gemini。还有图像、音频、向量、重排、Realtime 与任务接口。具体请求路径见 [API 概览](/api/)。

RelayKit 承担协议转换，但工具定义、推理字段、多模态内容和流式事件并非总能一一对应。先选择上游原生支持的协议；需要转换时，对应用实际用到的字段逐项验证。
