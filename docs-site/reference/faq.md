# 能力边界与常见问题

## Ai-gateway 会提供模型额度吗？

不会。你需要自己有权使用的上游服务、凭据和预算。用户在网关内获得的额度也不会自动为服务商账号充值。

## 为什么用上游密钥调用网关失败？

客户端应持有网关创建的 API 令牌，上游密钥保存在渠道内。两者属于不同系统，不能混用。

## 是否所有模型都支持所有接口？

不是。接口可用取决于路由、渠道适配、模型能力、转换路径和上游权限。测试通过一个 Chat 请求，不代表工具、图片、Responses 状态存储或 WebSocket 都可用。

## Files 和微调可以直接用吗？

当前路由中的通用 `/v1/files`、`/v1/fine-tunes` 和 `/v1/images/variations` 由未实现处理器响应。它们出现在旧教程或 OpenAPI 中，也不能当作当前已实现功能。

## token 计数接口是否支持？

当前 Claude `/v1/messages/count_tokens` 没有启用，Gemini `:countTokens` 被明确拒绝。TokenKit 是内部独立模块，不代表相应外部 HTTP 端点已经提供。

## SQLite、MySQL、PostgreSQL、ClickHouse 怎么选？

前三者可作主数据库；ClickHouse 仅作独立日志库。小规模评估可从 SQLite 开始，现有运维系统也可选择 MySQL 或 PostgreSQL。迁移不是只修改一个 DSN，必须保留数据并验证恢复。

## 这个项目与上游 New API 完全一样吗？

不是。当前项目已经有不同的前端、认证、模块拆分、计费和任务插件实现。安装命令、页面位置、配置行为与上游文档可能不同。本手册按当前源码编写；上游署名、历史协议和存储标识按许可与兼容性保留。

## 文档站会替换当前管理界面吗？

不会。`docs-site` 是独立静态项目，构建后可放在单独域名或 `/manual/`。控制台默认文档路由的行为没有改变；部署完成后再配置导航入口。

## 为什么没有列所有服务商最新模型和价格？

模型可用性、命名与价格持续变化；未经实时验证的列表容易误导。本文档重点解释配置与核对方法，实际发布模型以渠道、令牌和服务商授权为准。

## 这是外站的完整镜像吗？

不是。本手册覆盖部署、管理、接入与运维主线，使用当前项目事实重新编写。没有复制外站所有文章、截图、商业内容、社区列表或实时更新。具体覆盖范围与维护方式见 [内容来源与维护](/reference/maintenance)。
