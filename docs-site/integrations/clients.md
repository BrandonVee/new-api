# 通用客户端配置

大多数支持自定义 OpenAI API 地址的客户端，可以通过修改地址、密钥与模型接入网关。不同客户端对地址后缀的处理不同，应检查最终请求。

## 三个必要值

| 配置 | 填写内容 |
| --- | --- |
| API Base URL | 通常为 `https://gateway.example.com/v1` |
| API Key | Ai-gateway 控制台创建的网关令牌 |
| Model | 令牌允许且渠道可路由的模型名 |

如果界面明确要求完整端点，就填写它要求的形式；如果会自动追加 `/v1`，则按其实际行为填写根地址。不要机械地给所有客户端增加相同后缀。

## 聊天客户端

以 Cherry Studio 等允许自定义服务商的工具为例，选择合适的兼容类型，填入上述三个值，先发一条纯文本消息。再逐步测试图片、工具、文件或联网能力。

客户端的“文件”功能可能只在本地解析文档，也可能依赖 `/v1/files`。当前网关并未实现通用 Files 接口，不能保证所有附件模式可用。

## 知识库与工作流

在 Dify 等支持配置模型服务的系统中，分别配置聊天、向量和重排模型。模型发现、embedding 维度、批量输入和超时都应逐项验证。

工作流服务若运行在容器内，`localhost` 指向它自身，不是网关容器。使用同一网络中的网关服务名、可访问的宿主机地址或正式 HTTPS 域名。

## 编程与代理客户端

先确认工具支持自定义服务地址，以及实际使用 Chat、Responses、Messages 还是其他协议。客户端可能依赖 token 计数、Files、特定内置工具或 WebSocket；不能仅凭“兼容 OpenAI”四个字推断全部功能可用。

配置 API 入口不会替代客户端自己的订阅、登录或产品授权。先用最小 API 请求确认网关可用，再排查客户端专用能力。

## 建议验证顺序

模型列表 → 单轮纯文本 → 流式 → 多轮 → 工具或图片。每增加一项能力就检查日志。客户端失败而 curl 成功时，对比 URL、模型、鉴权头、请求字段和流式解析方式。
