# 1Panel 与宝塔面板

面板负责容器编排、证书和反向代理。Ai-gateway 的渠道、模型与用户配置仍在网关控制台完成。不同面板版本的入口名称可能不同，下面按实际需要完成的任务组织。

## 推荐流程：使用 Compose 项目

1. 将当前仓库放到服务器上的固定目录。
2. 在面板中使用现有 Compose 文件创建编排项目；如果面板不能从源码构建，先在服务器终端执行 `docker compose build`。
3. 按 [Compose 部署](/deploy/compose) 替换服务密码、连接串、会话密钥和端口绑定。
4. 启动项目，检查网关、数据库与 Redis 日志。
5. 为正式域名配置证书与反向代理，连接到网关的内部端口。
6. 访问控制台初始化，再测试流式请求。

## 在 1Panel 中注意什么

使用容器编排功能管理 Compose 项目；文件上传后核对相对挂载目录的解析位置。反向代理可以通过网站管理配置，但流式输出和 WebSocket 需要检查生成的 Nginx/OpenResty 配置。

如果应用商店条目指向其他维护者的镜像，那不是当前源码的构建结果。要使用本项目功能，应使用自己的构建与版本标签。

## 在宝塔中注意什么

确认 Docker/Compose 插件可用，或通过终端管理容器。网站反向代理目标必须与网关监听地址一致；开启证书后，核对代理是否转发正确的协议头。

不要同时通过面板与终端创建两个同名但挂载不同的实例。面板迁移、重装或重新导入 Compose 项目之前，记录原项目名和卷名。

## 完成后的检查

- HTTPS 证书有效，HTTP 可按需要跳转到 HTTPS。
- 代理没有缓存 API 响应，流式内容能逐段到达。
- 数据库和 Redis 只在受控网络可访问。
- 你知道数据库实际位于哪个目录或卷，并完成了恢复演练。
- 容器重启后，已创建的管理员、渠道和令牌仍然存在。

反向代理参考配置见 [HTTPS 与反向代理](/deploy/proxy)。这里没有声称验证过某个面板版本的一键安装流程。
