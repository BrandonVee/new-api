# 日志与用量分析

排查一次调用时，先找到对应时间和请求，再关联模型、渠道、状态、耗时与用量。聚合图表适合观察趋势，单次日志适合定位原因。

## 从一次请求开始

1. 记录调用时间、模型、HTTP 状态和客户端返回的请求或任务标识。
2. 在日志页面按时间、模型、令牌或用户过滤。
3. 管理员再检查实际命中渠道与上游错误。
4. 对任务请求，同时查看任务页面的最终状态。

权限不同，可见字段也不同。普通用户无法看到某些管理诊断字段，不代表字段没有记录。

## 各种记录的用途

| 记录 | 主要用途 |
| --- | --- |
| 使用日志 | 查看模型、用量和结算结果 |
| 错误日志 | 确认失败原因和上游响应 |
| 系统文件日志 | 排查启动、连接、轮询和后台异常 |
| 审计日志 | 追踪管理操作和安全相关事件 |
| 仪表盘统计 | 观察请求量、费用、性能趋势 |

不同记录的保存位置和保留策略可能不同。控制台清理某类记录，不等于清理了数据库和磁盘上的所有日志。

## 正确理解时间与用量

首字延迟、总响应时间和任务耗时不是同一个指标。客户端看到的时间还包含网络和代理开销；不要直接把客户端总耗时当成上游首字延迟。

流式中断、缓存使用、协议转换和后台任务会影响 usage 记录。核对费用时查最终结算信息，避免仅以输出文本长度估算。

## 对外提供排障材料

提供版本、部署方式、时间范围、接口路径、HTTP 状态、复现步骤和脱敏日志。移除 `Authorization`、API Key、Cookie、验证码和可直接访问私有产物的链接；不要直接转发完整 HAR 或请求环境文件。
