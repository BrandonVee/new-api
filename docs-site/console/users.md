# 用户、分组与权限

用户权益、管理权限与 API 令牌限制各自解决不同问题。分配时从最小需要开始，避免为了让一次请求通过而授予管理员权限。

## 创建与启用用户

按实例的注册策略创建用户，检查账户状态、可用额度或订阅，以及允许的分组。普通使用者不需要渠道密钥查看权限，也不需要修改系统配置的权限。

如果用户不能调用模型，先查账户状态、分组和额度，再看令牌限制与渠道，不要先改变角色。

## 分组怎样影响调用

分组连接用户与渠道，也可能影响价格。配置后要核对：

1. 用户是否可以使用目标分组。
2. 令牌请求使用的分组是否正确。
3. 渠道是否包含这个分组。
4. 目标模型是否在该分组存在可用渠道。

同一个模型在不同分组下可能命中不同渠道或适用不同价格。修改用户所属分组不等同于修改每个渠道的分组配置。

## 权限管理

当前项目在角色基础上支持细粒度授权，后台实现位于 `service/authz/`。页面是否显示一个操作不代表服务端一定允许它；实际权限由后台检查决定。

区分日常运维、财务查看、模型维护与用户管理等职责。发放 PAT 时应明确调用目的，妥善保管，并以当前管理接口支持情况为准。

## 登录设备管理

控制台支持登录会话管理，也支持配置 MFA、Passkey 和第三方登录。用户离职、设备丢失或发现异常时，应按具体情况禁用账户、撤销会话并处理相应 API 令牌。

登录会话与模型令牌不是同一对象。撤销某台设备的登录会话后，不应假定先前发放的所有模型令牌都已被撤销；应分别检查和处理。
