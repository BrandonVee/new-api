# 创建与管理 API 令牌

API 令牌供应用调用网关模型接口。每个应用、环境或用途使用独立令牌，才能在停用、限额和排障时缩小影响范围。

## 创建令牌

打开控制台的 API 令牌管理，创建并填写：

- 名称：区分调用方，例如 `knowledge-base-prod`。
- 有效期：按使用周期设置，临时测试不需要长期有效。
- 可用额度：为该令牌设置预算；它仍受用户权益限制。
- 分组：选择用户有权使用且能匹配渠道的分组。
- 模型限制：只允许应用需要的模型。
- IP 等访问限制：按实际部署出口配置，并检查反向代理来源识别。

创建后按控制台提供的方式复制令牌。密钥展示与二次验证要求以当前权限为准，不要假设所有成员都可随时查看已有密钥。

## 验证后交给应用

先用令牌请求 `/v1/models`，再对一个允许的模型发出实际请求。把网关地址与令牌配置到应用后，查看对应调用日志。

“令牌无限额度”不表示用户余额无限，也不会绕过分组权限、模型限制、上游限流和订阅规则。

## 保存位置

服务端应用通过进程环境或密钥管理服务读取令牌。不要写进浏览器前端代码、公开配置仓库、示例截图或公开文档。

面板 Access Token、PAT 和模型 API 令牌属于不同凭据。管理自动化不要随意复用给应用的模型令牌。

## 轮换与停用

创建新令牌 → 在受控调用方切换并验证 → 停用旧令牌。轮换时观察失败率和日志，避免留下仍在使用旧令牌的计划任务。如果密钥泄露，应立即停用并检查异常使用，而不只是修改显示名称。
