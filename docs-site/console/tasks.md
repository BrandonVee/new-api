# 任务与插件

图像、视频等能力可能通过 JavaScript 任务插件接入。插件声明支持的模型、动作、请求格式和查询方式；宿主负责路由、鉴权、任务保存、轮询与结算。

## 使用前检查

进入插件相关管理页面，确认需要的插件已经安装并成功加载。然后创建对应渠道，填写服务商凭据、可用模型和分组。插件已安装不代表渠道已配置，也不代表模型已经定价。

插件市场中的条目与已安装状态是两件事。插件版本、网关版本与协议扩展需相容；加载失败时查看系统日志，而不是反复创建渠道。

## 选择调用方式

| 方式 | 适用情况 |
| --- | --- |
| `/v1/tasks/{pluginKey}` | 使用统一任务提交与查询流程 |
| `/v1/images/generations` 等宿主协议 | 插件声明兼容接口，供现有客户端使用 |
| 插件原生路径 | 应用需要供应商专有的请求或响应格式 |

原生路径与请求体由插件声明，不能把所有插件都当作同一种 JSON。具体调用见 [异步任务 API](/api/tasks)。

## 关注任务状态而非一次 HTTP 结果

提交成功只说明任务已被接受。后台还可能排队、执行、失败或超时。客户端应保存网关任务 ID，按合理间隔查询，终态后停止轮询。

部分兼容协议会在同一个 HTTP 请求内等待任务完成。此时客户端超时后任务仍可能继续运行和结算，应先查询状态再重试。

## 插件维护者

当前插件契约为仓库 `docs/plugin-api/v1.md`，类型和 JSON Schema 分别在同目录的 `.d.ts` 与 `.schema.json`。开发前必须阅读完整契约；不要把旧版外站示例直接复制进当前运行时。

数值用量字段描述用于价格输入标签，应说明“计费对象 + 单价”；单位放在 `unit`，技术细节放代码注释。升级插件前应保存版本与配置，并核对在途任务的查询兼容性。
